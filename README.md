# AI 需求雷达

自动盯评论、抓痛点、把「哪些需求被最多人提到」排出来的一套本地系统。

你给关键词，它 7x24 不定时地去公开评论场子捞新内容，用大模型把每条里藏着的痛点抽出来，
归并成独立需求，按被提到次数排序，最后给一个本地网页看板 + 一份 Markdown 排行。

## 它实际挖出过什么

连续跑三天的真实数据（2026-09-25 起）：

| 指标 | 数值 |
|---|---|
| 原始评论 | 621 条 |
| 抽出的需求 | 291 条 |
| 其中**隐性需求** | **82%** |
| 归并后独立需求 | 253 个 |
| 单轮成本 | 约 ¥0.5（一天 12 轮 ≈ ¥6） |

「隐性需求」= 用户没抱怨任何东西、需要模型从一句平常话里推出来的那种。举例：

> 原文：**"不建议用AI写作"**
>
> 模型从这一句推出两条：**「AI 生成内容要能过平台原创检测」**、**「平台需明确 AI 辅写红线」**
>
> 用户一个抱怨的词都没用，但暴露了「怕被平台判违规」这个真需求——这才是能拿去做产品的线索。

每条需求都带 `reasoning` 字段，写明"从原文哪个动作推出来的"。**说不出依据的，就是模型在编。**

```
搜索/帖子 ──► 采集器 ──► 去重脱敏 ──► 痛点闸门 ──► 大模型抽取 ──► 需求聚类 ──► 排行看板
   贴吧           SQLite        （省 API 钱）      DeepSeek      同一种说法算一条
   B站评论
   Bing 全网发现
   自定义网页
   浏览器导入
```

## 一、三步跑起来

### 1. 装依赖
```bash
pip install -r requirements.txt
```

### 2. 给它一个大模型的钥匙（**这一步决定质量，不能省**）

**密钥放 `config/secrets.yaml`，不要放进 `config/config.yaml`。**

原因是 config.yaml 里全是业务配置（关键词、开关），你会反复改、可能会截图发给别人看；
密钥单独一个文件就不会跟着一起漏出去。`secrets.yaml` 的优先级高于 `config.yaml`。

```yaml
# config/secrets.yaml
llm:
  base_url: "https://你的网关/v1"
  api_key: "sk-xxxxxxxx"
  model: "deepseek-v4.1-flash"
```

任何 OpenAI 兼容网关都能用（官方 DeepSeek、各种中转都行）。不确定网关挂了哪些模型，
先查一下：
```bash
curl https://你的网关/v1/models -H "Authorization: Bearer sk-xxxxxxxx"
```
**注意**：`/models` 列出来的才是能用的。配置里写了列表里没有的模型名，会直接 404。

第三方网关有三处和官方不一样，已经在代码里处理了，换网关时留意：

| 坑 | 表现 | 处理办法 |
|---|---|---|
| 模型名不对 | `Model "xxx" is not supported by any configured account` | 以 `/models` 返回为准 |
| 输出慢（尤其推理模型） | 归并批量大时 `APIConnectionError` | `llm.timeout` 放宽到 180 秒 |
| 推理模型把思考过程混进回答 | 返回体开头是一段分析文字，解析出空数据 | 解析器会自动挑出其中最完整的那个 JSON 数组 |

另一种方式是环境变量，密钥完全不落盘：
```powershell
$env:OPENAI_API_KEY = "sk-xxxxxxxx"
```

没有 key 也能跑，会退化成正则规则抽取——**能用，但只抓得到"用户明说的抱怨"，
抓不到真正意义上的隐性需求**。这二者的差别见第六节。

### 3. 跑一轮看看
```bash
python run_once.py --keywords "AI工具,AI写作"
```

跑完打开 `data/export/latest.json` 或 `data/export/report_YYYYMMDD.md`。

### 4. 开看板
```bash
python server.py
# 浏览器打开 http://127.0.0.1:8777
```

### 5. 挂着不关（7x24 不定时）
```bash
python daemon.py
```

想后台常驻、不要那个黑窗口：Windows 用 `pythonw daemon.py`，
Linux/macOS 用 `nohup python daemon.py > /dev/null 2>&1 &`。
日志都落在 `logs/YYYYMMDD.log`。

## 二、你要改的通常只有三件事

全在 `config/config.yaml`：

| 想改什么 | 改哪儿 |
|---|---|
| **换成别的行业**（餐饮、母婴、SaaS…） | `topic.name` + `topic.keywords`（关键词列表，随便加） |
| **用什么标准放行评论** | `gates.mode`（默认全部送审，详见第七节；改 `hints_only` 可省钱但丢隐性需求） |
| **多久扫一次** | `schedule.rounds_per_day`（默认一天 12 轮，间隔带 ±45% 抖动） |

常用参数：

```bash
python run_once.py --keywords "AI视频"              # 只跑某几个词
python run_once.py --source-only tieba              # 只跑一个源（调试用）
python run_once.py --consolidate                    # 跑完做一次需求归并
python run_once.py --dry-run                        # 只采集不抽取，看能抓到什么
python run_once.py --set sources.tieba.pages=3      # 临时覆盖任意配置
```

## 四、合规边界（**默认配置，别乱改**）

系统默认按「低频、只读、公开、匿名、只出聚合」设计：

- 同一域名两次请求之间**强制随机休眠 3~8 秒**，单域名每小时上限 150 次；
- **不做聚焦岗位画像**，只输出「需求 → 被提到多少次」的聚合统计；
- 入库前自动打码手机号 / 邮箱 / 身份证 / 微信号，作者只存哈希，**不存原始昵称**；
- **不破解任何登录、不绕过验证码**，遇到 403/432/风控页直接跳过并记录；
- 默认尊重 robots.txt。

### ⚠️ 唯一一处要你自己拍板的地方

**`api.bilibili.com` 的 robots.txt 明写着 `User-agent: * / Disallow: /`** —— B 站官方明确不允许程序化抓取它的接口。

目前配置里默认把它放进了白名单（`compliance.robots_overrides`），好让你先跑得起来。

如果你不接受这个风险，把那个列表清空：

```yaml
compliance:
  robots_overrides: []      # 改成这样，B站采集立即停用，其余功能完全不受影响
```

法律层面提醒一句：大规模抓取平台用户评论，如果涉及个人信息或用于商业竞争，会碰到
《个人信息保护法》《数据安全法》《反不正当竞争法》。**自用做产品洞察没问题，
对外售卖或大规模存储原始个人信息要谨慎。** 这套系统已经帮你把个人信息降到了最低（脱敏 + 只出聚合）。

## 五、小红书 / 知乎 / 微博：走浏览器通道

这三个站点反爬强，明文请求必被拦。正确做法是**用你本机已经登录的真实浏览器**去抓，
结果导成 JSON 丢进 `data/inbox/`，系统自动接进主流水线。

JSON 格式（数组或单个对象都行）：

```json
[
  {
    "source": "xiaohongshu",
    "url": "https://www.xiaohongshu.com/explore/xxxx",
    "title": "AI工具真的难用到爆炸",
    "content": "求推荐一个能批量处理表格的AI，试了三个都不行…",
    "author": "某用户",
    "published_at": "2026-09-25T20:00:00",
    "keyword": "AI工具"
  }
]
```

放进来就行：

```bash
python import_raw.py dump.json --run
```

（`source` 不填会自动从 URL 猜平台名；csv 也一样支持，列名同上。）

处理完的文件会归档到 `data/inbox_done/`。

## 六、看板里那几列是什么意思

| 列 | 含义 |
|---|---|
| 需求 | 大模型把不同说法归并后的标准短语 |
| 提及次数 | 这个需求被多少条评论提到（去重后） |
| **隐性** | 这条需求有多大比例是「AI 从用户没抱怨的话里分析出来的」 |
| 痛感 | 1~5 平均分，5 = 用户已经在找解决方案 / 愿意付费 |
| 趋势 | 后半段 vs 前半段的增长率，**红=在升温** |
| 来源 | 这个需求在几个不同平台都被提到（跨平台印证，可信度更高） |

点需求名可以展开看**原始评论原文 + 大模型的推导过程（reasoning）**，能直接跳转。

用顶上的下拉可以只看「挖出来的」——那一栏才是别人还在忽视的机会。

### 时间窗口要选「全部时间」

库里 `day` 存的是**原帖发布时间**，全网抓来的帖子跨度可能有十几年。
默认的「近 30 天」会按发帖时间把老帖滤掉——首次跑起来时会漏掉一大半数据
（实测 231 条需求里只剩 100 条）。

所以看板下拉里第一项是 **全部时间**。想知道"这个领域到底被反复抱怨什么"用全部时间；
想看"最近在升温什么"再用近 7/30 天。

## 七、为什么默认不用痛点词预筛

这是整套系统最重要的一条取舍，写在 `config/config.yaml` 的 `gates.mode`。

**显性痛点是最没价值的信号。** "太难用""太贵""求推荐"——你能在评论里搜到，你的竞争对手也能搜到。
围着这些做产品，是在红海里比谁手快。

真正值钱的是这种：

> "我现在写周报都先用 AI 生成一遍，然后自己改，改的时间跟重写差不多。"

里面一个抱怨的词都没有。但它暴露的东西，比一百条吐槽都实在——
用户已经接受了 AI 进入他的工作流，卡住的不是"能不能生成"，而是"懂不懂我"。

所以系统的做法是：**闸门只剔除垃圾（广告、灌水、"哈哈哈"），剩下的全部交给大模型去读懂。**
判断是否换别的方式/

代价是贵：所有评论都过了大模型，用量大约是"只筛痛点词"的 3 倍。
DeepSeek 上一轮 200 条评论大概 ¥2，一天 12 轮 ≈ ¥25/天。

如果你确实要省钱，把 `gates.mode` 改成 `hints_only`。
**但请知道你省掉的是什么**：恰好是那些用户自己都没意识到、最难被对手复制的那部分。

判断一条发掘是否可信，看它的 `reasoning`——模型必须说出「从原文的哪个动作推导出来的」。
说不出依据的，就是它在编。

## 八、目录结构

```

├── config/config.yaml        ← 所有开关都在这里
├── config/watch_urls.txt     ← 常驻盯梢页面

├── daemon.py                 7x24 守护
├── server.py                 看板服务
├── import_raw.py             浏览器通道导入
├── src/
│   ├── config.py / storage.py / http.py / clean.py / llm.py
│   ├── sources/              tieba / bilibili / searchengine / genericpage / browser_import
│   ├── pipeline/             cluster.py（需求归并）/ stats.py（统计）
│   └── runner.py             一轮编排
├── tools/                    接口探测脚本（调试新增平台时用）
├── data/demand.db            SQLite 单文件库
├── data/export/              报表（latest.json + report_日期.md）
└── web/index.html            看板页面（纯原生，不依赖 CDN）
```

## 九、想加新平台怎么办

1. 先用 `tools/probe_endpoints.py` 探一下目标站的公开接口/页面能不能拿；
2. 在 `src/sources/` 里照着 `tieba.py` 写一个类，实现 `collect(keywords)` 返回 `RawItem` 列表；
3. 在 `src/sources/__init__.py` 的 `REGISTRY` 里登记；
4. 在 `config/config.yaml` 的 `sources` 下加一段开关。

全程不动其他任何代码。
